## Sandbox Missteps & Troubleshooting (Lessons Learned)

During initial testing inside an isolated sandbox environment, several barriers prevented the log file from populating properly. Below are the key takeaways from those missteps:

    Misstep 1: Environment Variable Isolation via GUI Launchers

        Issue: The SSLKEYLOGFILE variable was initially exported inside a standalone terminal session. Launching the target application via a desktop shortcut or GUI launcher bypassed that terminal's context entirely, causing the application to run without the logging environment instruction.

        Correction: Applications must be executed directly from the terminal where the variable is active, or the export must be defined globally in /etc/environment.

    Misstep 2: Application Containerization (Snap/Flatpak Strict Confinement)

        Issue: Sandboxed testing environments often run browsers containerized via Snap or Flatpak. Their strict security containment policies prevent the application from writing to hidden local user directories (~/sslkeys/), resulting in silently dropped logs.

        Correction: The workflow was shifted to the main host (gideon930@ajones), running native binary packages that possess standard user-space disk write privileges.

    Misstep 3: Zombie Application Instances

        Issue: Opening a new window while a background process or quick-start daemon of the application was already residing in memory forced the new window to inherit the old, unconfigured process environment.

        Correction: A full process cleanup (killall <application>) must be executed before exporting variables and starting a fresh session.
